Add a standalone adversarial review extension. `/adversarial-review` runs a hardened fetch-aware Git preflight before model selection: it infers feature-branch versus default-branch targets, asks TUI users about ambiguous or risky states (including `main`/`master` ambiguity), fails headless ambiguity loudly, disables repository/environment fetch execution hooks and helpers, binds the decision to HEAD/status/ref/patch fingerprints across model selection and freezing, and supports explicit offline `--local`; then it freezes local, base, or range Git input and selects two to eight exact scoped model/thinking routes through either a TUI picker or explicit flags; validates every reviewer report; deterministically clusters findings; applies weighted or strict health and consensus gates; detects drift; and shows aggregate progress with explicitly confirmed whole-run Escape cancellation. A compatible installed protocol-v3 Subagents extension supplies shared queueing and FleetView; when it is absent or incompatible, the command automatically uses the same caller-owned execution core through a side-effect-free embedded backend, without adding Agent tools or Subagents UI. Picker routes start disabled and first enable at `medium` or the nearest supported thinking level, while session-remembered and scope-pinned choices keep their constraints. Every reviewer receives the same complete evidence-first adversarial charter at system-prompt priority, the same frozen evidence, and the same task prompt, then independently completes the full attack surface without route-specific duties; clustering and votes happen only afterward, so agreement represents cross-validation rather than coordinated specialization. Explicit severity, confidence, and category calibration reduces model-specific rating drift, while the weighted single-high exception requires severity and confidence to coexist on the same original finding. The ordinary TUI setup enables Refute by default with the current main-session model and exact thinking level, falls back to scoped selection when that route is unavailable or incompatible, offers an interactive model override or disable choice, then runs one fresh isolated refuter per blocking cluster without removing findings; explicit/headless routes retain deterministic `--refute --refuter` control. TUI visibility is layered without duplication: one bounded run card owns aggregate phase/count/elapsed state, a discrete `Snapshot → Review → Gate → Finish` stepper (inserting Refute only after it starts, with no fake percentage), the target, frozen input, deterministic gate/Refute outcomes, and real cleanup without occupying Pi's footer status area; external Subagents Agents/FleetView exclusively owns per-agent execution and drill-down, while the embedded fallback retains bounded per-agent status in the Review card. A durable non-model-context dispatch entry records the exact frozen target and routes immediately before reviewer spawn, while readable report/cancellation/error entries close the transcript lifecycle; failed report summaries expose route errors before expansion, expanded reports include every route outcome and complete findings, and the adjudication handoff stays hidden to avoid duplicating the visible report. Confirmed cancellation preserves the partial audit but never triggers a main-model adjudication turn. Refute appears in live status only after it actually starts; skip reasons, valid attempts, and contested counts remain explicit in completion notifications and collapsed or expanded reports. The bilingual README is now a quickstart and links to packaged bilingual reference documents for the complete command, runtime, audit, and Git-safety contract. The final audit records backend/fallback reason plus routes/concurrency/waves and, outside print mode, is automatically handed to the current main model under fixed evidence-first, no-fix/no-commit instructions. Every non-TUI report/error is atomically persisted in a private standalone audit store independent of Pi's session flush policy; print/JSON operational failures also write control-safe stderr and set a non-zero process status. TUI users can pass bare `--range` to open a fixed-HEAD commit line directly, and ordinary setup offers the same line instead of an automatic batch plan when its inferred feature-branch target is large; users can choose any first-parent start commit without writing refs or hashes; the endpoint is fixed to the captured full HEAD, every row states `Start <sha> · reviews N commits`, feature-branch choices stop at the freshly fetched default-branch merge-base when provable, and the selected start commit is included through immutable full parent..HEAD SHA endpoints. The complete selected start-to-HEAD range remains one review target and one report: above the 200 KiB / 5,000-line recommendation, TUI confirms reviewing all N selected commits together or reopens the same commit line with closer starts; above the 1 MiB / 25,000-line hard limit, it must choose a closer start, and this path never silently invokes automatic batching. Explicit large `--base` and `--range A..B` targets retain deterministic commit-plan diagnostics for users who intentionally want separate runs. Every displayed choice retains a full-SHA identity, headless runs remain explicit, and approved large targets use 40 reviewer turns with 20/30-minute route/overall limits and 20 refuter turns with 10/30-minute limits, while ordinary limits remain unchanged. Hardening also covers raw Git patch capture, disabled textconv/content filters/fsmonitor, binary/LFS/submodule limits, and committed-only ranges whose B endpoint must be reachable from the current named branch HEAD before model selection. Every range, including clean B=HEAD, gives all reviewers and refuters one extension-owned detached linked worktree at B without changing the original index, files, branch, or HEAD. Linked checkout creation enforces fixed 100,000-entry and 2 GiB raw logical-data prelimits, an additive 512 MiB + 2× raw-byte temporary-filesystem reserve, a deterministic common-Git admin/index reserve, and a live 512 MiB reset floor; it atomically records pending intent before race-free token-locked add, then uses a hardened non-recursive reset with hooks, configured filters/LFS smudge, live symlinks, CRLF conversion, submodule recursion, replace refs, optional locks, and inherited Git path/config environment disabled. Worktree-first cleanup removes and verifies only the exact token-proven registration, clears ownership state before deleting the run directory, and supports retry/TTL cleanup after final directory deletion fails; current-cwd/live-PID checks plus quarantine-time `.git` revalidation preserve substitutions and unproven worktrees without broad prune. Cancellation keeps abort-identity-checked minimal durable pre-freeze audit behavior and separately classified cleanup failures; the package also retains explicit run-stage Escape confirmation, narrow leading-prose plus single-JSON-fence parser compatibility, a 30-second Review-only embedded terminal deadline that retains frozen input and any detached worktree on cleanup timeout, strict UTF-8 raw-output bounds, durable renderer recovery, and compatibility/rollback guidance. The package is intentionally not included in the root extension bundle.
