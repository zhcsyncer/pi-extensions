# R2：Pi 1.2+ 可编排子任务与当前配置授权

**用户已确认实施范围。** 本合同替代此前 model-only、历史权限交集及旧版本任务迁移要求；当前状态只记在执行编排 §0。目标是复用已有任务管理器提供可靠的 harness 编排能力，不新造调度器或权限框架。

## 已确认决定

- `Agent`、`get_subagent_result`、`steer_subagent` 同时支持模型直接调用和 codemode 工具调用，取消 model-only 限制；不强制使用 codemode，不自动开启它。
- 当前版本任务恢复时，以**当前配置**决定工具授权，不再与首次运行的权限清单取交集。新增允许工具可用，撤销或禁止的工具不可用。
- 不做旧版本子任务的跨版本迁移，不以此作为本轮验收门槛；不主动转换、删除真实旧会话。
- 保留宽限提示、结算等待、运行时配置隔离和持久用量读取等已有合理修复；只在本次明确路径发现问题时定点调整。
- 本轮不切换本机全局 Subagents 来源。Fast 已确认且被全局引用，代码、配置及其工作树必须保持。

## 执行与恢复边界

1. 保留 child 的公开 `tool_call` 执行门禁，覆盖直接与嵌套路径；模型可见列表不是授权。保留实际注册所有者、builtin 集合、deny、扩展工具子集、晚注册与 pins 的含义。
2. 允许父会话脚本编排 Agent，不代表允许 child 递归创建 Agent；原 child 排除 Agent/get/steer 的限制保留。isolated/reviewer/format-repair 原有约束不放开，也不提前实现 R3 的原生 MCP 连接能力。
3. named 角色按原配置目录重新读取当前同名定义；当前角色不存在或已禁用时明确失败，不回退其他角色。原来源路径与旧工具列表不作为额外历史上限。
4. inline 角色没有独立磁盘模板，以调用方给出的当前定义为优先，活实例可复用其当前定义；未提供替换定义时，保存的任务定义可以继续作为该任务的定义，不以保存的授权清单限制新配置。不能凭空扩大成全权限默认角色。每次调用仍核对当前授权与实际工具归属。
5. 当前配置授权不自动替换原任务的模型、cwd、system prompt、上下文、轮次限额或历史结果。保留首次实际生效的任务显式隔离选项，但不得把角色当时的默认隔离永久固化为调用方限制；首次调用现有优先级不变。当前角色默认取消隔离后，未显式要求隔离的任务冷恢复可使用当前允许的扩展，显式隔离任务仍不能。
   已确认的资源边界：已注册工具的授权放宽/撤销在热续跑生效；此前未加载扩展、未完整发现的加载集合扩大时，热续跑明确提示冷恢复或新任务，持久任务冷恢复按当前配置装配。当前SDK无公开替换loader入口，本轮不另造动态loader或自动重建会话，不用历史交集静默掩盖。
6. 不为旧 archive 猜测历史扩展所有者。删除不再需要的历史交集与重建分支，但不借此重写 SDK 的 session 解析器或取消当前版本正常恢复的损坏/路由保护。
7. inline/factory 来源的疑点仅验证现有公开接口真实可达的合法场景；不存在公开入口就记录不适用，不为假设新增扩展加载能力。不得为通过测试放开未知来源。

## 生命周期与统计合同

- 用真实 Pi 1.2 codemode → Agent 工具路径验证批量启动、后台返回 ID、取结果和追加消息；直接调用仍可用，继续使用原 manager 并发与任务归属。
- 取消/脚本结束/失败后，任务状态、结果与实际结算一致，不留下误报完成或未被管理的运行。以相同参数的直接 Agent 调用为正控，保持原有前台/后台取消语义；明确区分尚在等待的工具调用与已返回 ID 的受管理后台任务。不假定脚本失败会回滚已完成的工具调用，不新增自动停止后台任务、串行调度或隐式重试政策。
- 子任务、工具与独立 usage 的费用仍读真实持久记录。累计快照不是增量；父会话与 codemode 汇总必须只计一次。同一codemode调用的子任务与父侧普通工具费用都须保留；验证完整父会话统计，不仅求和toolResult而漏掉独立usage条目。收据表示子账份额，不得把混合费用整笔当子代理rollup扣除。
- 真实SDK确认：codemode父结果自动汇总native usage，但不保存子结果details收据。公开tool_result/message_end传播收据至实际父条目，不重新累计用量。收据与实际承载用量同存，不提前写虚假已报账记录。
- **必要配套例外（已实测）**：Meter共享session-parser只认识直接Agent/get转报，导致混合父0.07+子0.05记为0.12、续跑总0.09记为0.16。允许最小生产者/消费者适配：子收据新增可选`reportedUsage`，内容为本次实际返回的native Usage增量（不是cumulative）；当前生产者总是提供，现有watermark语义不变。Meter只从带有效增量收据的混合父条目扣除这些子份额，保留父工具自己的费用。tokens和cost一起处理，来源entry身份不变；缺失/无效增量不得猜测或用累计数相减，不制造负数或把未知成本变成已知零。不改SDK原始usage，不修改历史日志或既有账本，不重做存储/计价/配额。Meter其它改动仍待逐包确认。
